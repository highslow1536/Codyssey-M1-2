# 백엔드·바닐라 웹 UI 검증

최신 검증일: 2026년 10월 22일. 아래 초기 데이터·웹 검증은 10월 21일 기록이며, 새 리서치 통합 결과는 별도 절에 기록한다. Python 3.12.14, 프로젝트 `.venv`와 `uv.lock` 사용.

## 실제 수집과 저장

Yahoo Finance를 yfinance로 실제 호출했다. 합성 시세나 장애 대체 데이터는 사용하지 않았다. 최근 1년의 완료된 거래일을 수집해 **로컬 공식 Firestore 에뮬레이터**의 `market_bars` 및 사용자 `data`에 저장했다.

`jobs.verify_data --check-reimport`로 저장된 원본을 다시 가져와 9개 대상 모두 추가 생성 0건, 원본 변경 0건을 확인했다. 동일 필터의 전체 요약·출처·고유 날짜 수도 확인했다. 현재 작업 디렉터리의 `artifacts/firestore-verification.json`에 기계 판독용 결과가 있다. 이 폴더는 로컬 점검 산출물이며 버전 관리에서 제외한다.

테스트용 DB는 `demo-stock-assistant`, Firestore 에뮬레이터 v1.19.8, Java 17을 사용했다. 검증 후 임시 서버는 종료했으며 실제 원본 2,235건을 `artifacts/yahoo-all-real-bars.json`에 보관했다. 자신의 개발 환경에서는 수집 CLI를 다시 실행한다. 클라우드 저장 완료를 의미하지 않는다.

현재 Starlette TestClient에서 httpx 사용에 관한 지원 중단 예정 경고 1개가 있다. 테스트 실패는 없으며 경고를 숨기는 설정은 추가하지 않았다.

## 바닐라 웹 UI

프레임워크 없이 HTML/CSS/ES modules로 구현했다. 실제 Chrome에서 데스크톱 1440px·모바일 390px 화면을 검증했다. 공식 Firebase 웹 SDK 12.19.0을 CDN에서 로드하고, **공식 Authentication 에뮬레이터의 이메일 로그인 → 실제 ID token → Admin SDK 검증 → FastAPI → 공식 Firestore 에뮬레이터** 경로를 사용했다. 인증 함수나 데이터 API는 대체하지 않았다.

- 실제 Yahoo 응답을 보관한 AAPL 3건으로 시작하고 화면의 수집 버튼으로 Yahoo를 다시 호출했다. 동일 기간 재수집은 중복 기록을 만들지 않았다.
- 기간 조회·전체 평균/최고/최저/관측 수·차트, 직접 입력·수정·삭제를 확인했다. 다른 클라이언트의 수정으로 409를 발생시켜 최신 목록 복원도 확인했다.
- 메모의 `<img onerror=...>` 입력이 코드로 실행되지 않고 텍스트로 표시됐다.
- 채팅 완료 응답을 브라우저에서 의도적으로 유실시켰다. 재시도가 동일 본문·요청 ID를 사용하고 대화에는 질문·답변이 한 번만 저장되는지 확인했다.
- 후속 질문, 새 대화, 새로고침 후 로그인 복원과 대화 재열기를 확인했다. **102개 메시지**가 두 API 페이지에서 순서대로 복원되는지와 대화 삭제를 확인했다.
- 로그아웃 시 데이터·대화 화면을 비웠고, 다른 계정에서는 이전 계정의 대화가 나타나지 않았다. 모바일 데이터·채팅 화면의 가로 넘침이 없음을 확인했다.
- 브라우저 스크립트 오류가 없었다. `artifacts/web-login-*.png`, `web-data-*.png`, `web-chat-*.png`에 로컬 증빙을 저장했다. 테스트 계정은 에뮬레이터 전용이다.

`frontend/tests/serve_api.py`에서 **모델 출력만 테스트 응답으로 대체**했다. 실제 OpenAI 응답 검증으로 계산하지 않는다. 이 파일은 운영 앱과 배포에서 참조하지 않는다. 실행 앱에는 가짜 로그인·시세·모델 답변 대체 경로가 없다.

웹 인프라 Node 검사 **27개 통과**: 공개 설정만 빌드에 출력, 서비스 계정 오입력 거부, API 토큰 첨부·401 갱신·인증 실패 시 요청 중단·중복 자동 재시도 금지·abort·오류 형식·비JSON 성공 응답 거부·로컬 인증 에뮬레이터 제한. Playwright 버전은 `frontend/pnpm-lock.yaml`로 고정했다. 기존 Python **46개** 회귀 검사와 ruff 검사도 다시 통과했다.

Firebase SDK 사용 방식은 [웹 인증 시작](https://firebase.google.com/docs/auth/web/start), [비밀번호 인증](https://firebase.google.com/docs/auth/web/password-auth), [인증 에뮬레이터 연결](https://firebase.google.com/docs/emulator-suite/connect_auth)을 확인했다. 재현 명령은 README의 웹 검사 절에 있다.

## 뉴스·심리·기술 지표 통합 (2026년 10월 22일)

실제 네트워크로 Yahoo의 S&P 500·VIX 최근 1년 완료 일봉을 각각 **251건** 재수집했다. S&P 500의 수익률·표본 로그수익률 변동성·이동평균·Wilder RSI·거래량 비율과 VIX의 변화·경험적 백분위를 계산하고 로컬 공식 Firestore 에뮬레이터의 원본 및 캐시에 저장했다. 이 조회는 사용자 편집 `data`를 만들거나 바꾸지 않는다.

CNN의 실제 JSON 피드는 HTTP 200을 반환했다. 실제 키 `fear_and_greed_historical`에서 **252개** 관측을 읽어 정규화·정렬하고 현재 값과 비교 값, 일별 `sentiment`, `research_cache`에 저장했다. 마지막 점검의 관측 시각은 2026-10-21 16:33:02 UTC, 성공 수집 시각은 16:38:50 UTC였다. 이 값은 검증 당시의 관측이며 현재 투자 정보로 표시하는 고정 예시가 아니다. `artifacts/cnn-live-source.json`·`artifacts/research-live-verification.json`에 로컬 증빙을 보관했다.

Naver·Finnhub 키는 아직 발급되지 않아 실제 뉴스 실호출을 실행하지 않았다. API 요청 헤더·기간·페이지·형식·HTML 정리·URL·중복 제거·429/인증/형식 오류는 **테스트 전용 페이로드**로 검증했다. 실제 앱은 키가 없으면 `news_not_configured`를 반환하며 시연용 기사를 생성하지 않는다. OpenAI도 실제 키가 없어 요약·채팅 모델 왕복은 테스트 응답으로 검사했다. 모델 미설정·실패·잘못된 기사 인용은 실제 제목·요약 발췌 모드로 처리한다.

- Python 전체 **102개 통과**(단위 86·Firestore 통합 16), ruff 검사·포맷·compileall 통과. Starlette TestClient의 httpx 지원 중단 예정 경고 1개는 남아 있다.
- 새 API 4개와 인증·필터 검증, 원본/사용자 데이터 분리, 캐시 기간·실패 후 재시도 억제·오래된 실제 데이터 보존·부분 장애·수집 임대·시도 토큰 차단을 검사했다.
- 뉴스가 기간 밖으로 이동하면 기사와 요약에서 함께 제거되는지, 빈 결과와 공급원 장애를 구별하는지 확인했다. CNN의 0점·실제 history 필드·오류 점수·미래 시각·이력 상한을 검사했다.
- 지표 표본 수 경계·비정상 값·날짜 중복·다른 종목 제외·Wilder 재귀와 RSI 보합/일방 상승/하락을 검사했다. 모델 도구 4개는 엄격한 인수 검증·사용량 상한을 유지한다. 뉴스 도구가 주 모델 예산 밖의 요약 모델을 추가로 호출하지 않는지와 요약 하이라이트의 출처도 보존하는지 검사했다.
- 채팅은 별도 외부 호출 없이 저장된 원본 리서치를 문맥으로 읽고, 도구로 얻은 출처도 답변·Firestore 메시지·대화 재조회에서 보존한다. 길이 제한 후에도 모델에 전달하는 JSON이 깨지지 않는지 확인했다.
- Node 검사 **27개 통과**. 기존 실제 Auth·Firestore·Yahoo 브라우저 검사를 채팅 변경 후 다시 통과했다.
- 새 `frontend/tests/research-browser.mjs`의 첫 단계는 실제 Auth·API·Yahoo/CNN 저장 데이터를 사용했다. 1440px·390px에서 실제 지표·CNN·VIX·뉴스 키 누락 상태를 확인하고 `artifacts/web-research-desktop.png`·`web-research-mobile.png`를 생성했다. 실제 리서치 출처가 채팅 응답에서 표시되고 새로고침 후 대화 재열기에서도 유지되는지 확인했다. 모델 문장은 격리된 서버의 테스트 응답이다.
- 같은 브라우저 검사의 이후 단계만 overview 응답을 명시적인 테스트용 페이로드로 바꿨다. CNN 0점, 오래된 데이터와 공급원 오류, 요약 인용·실패 안내, 악성 HTML의 텍스트 표시, javascript 링크 거부, 종목·기간 인수·로딩 상태, 실패한 조회에서 이전 종목 표시 제거, 로그아웃 중 늦은 오류 억제, 모바일 가로 넘침을 확인했다. 런타임 앱에는 이 응답 대체 코드가 없다.

통합 검사는 로컬 테스트 캐시를 초기화한다. 실제 브라우저 검증 전에는 실제 수집 증빙을 원래 수집 시각과 함께 복원했다. 이후 새 환경에서의 브리핑은 실제 공급원을 다시 조회한다. 검증용 서버와 에뮬레이터는 종료했다.

## Discord 예약 브리핑 (2026년 10월 22일)

실제 Yahoo·CNN을 조회해 한국 시장(KOSPI·KOSDAQ·삼성전자)과 미국 시장(S&P 500·NASDAQ·Apple·VIX·CNN) 브리핑을 생성하고 공식 로컬 Firestore 에뮬레이터에 저장했다. 한국 일봉은 마지막 완료 세션보다 오래되어 `stale`로 표시됐고, 미국 자료에는 관측 시각과 출처를 포함했다. Naver·Finnhub 키가 없다는 상태도 본문에 표시했다. 실제 기사·Discord 채널 수신·OpenAI 응답을 검증한 것으로 계산하지 않는다. 실제 생성 증빙은 로컬 `artifacts/briefing-live-previews.json`에 있다.

Discord 어댑터는 공식 [Execute Webhook](https://docs.discord.com/developers/resources/webhook#execute-webhook)·[Rate Limits](https://docs.discord.com/developers/topics/rate-limits)를 확인했다. HTTP 검사는 `httpx.MockTransport`로 요청의 `wait=true`·멘션 차단·메시지 ID·429 대기·인증 오류·5xx·타임아웃·비밀값 비노출을 검증했다. 런타임 앱에는 테스트 전송 응답을 주입하는 설정이 없다.

예약 계산은 실제 거래소 달력으로 한국 휴장일·미국 조기 폐장·서머타임을 확인했다. 지정 시각의 존재하지 않는 시간·두 번 반복되는 시간도 검사했다. 초기 구현의 370일 일괄 조회가 달력 지원 범위를 넘는 문제를 발견해, 가까운 날짜부터 14일씩 탐색하고 첫 유효 시각에서 멈추도록 수정했다.

브리핑 저장·전송은 공식 Firestore 에뮬레이터에서 소유권, 요청 키·revision 충돌, 페이지 cursor의 소유자 범위, 예약 슬롯 선점, 만료된 생성·전송 임대의 복구와 늦은 결과 차단, 성공한 부분 보존·실패한 부분만 재시도, 429 목적지 대기와 최대 5회 제한을 검사했다. 에뮬레이터는 클라우드 복합 인덱스 존재를 강제하지 않으므로 클라우드 배포 뒤 별도 조회 확인이 필요하다.

- 최종 Python **162개 통과**(단위 131·Firestore 통합 31), ruff 검사·포맷·compileall 통과. 기존 TestClient 지원 중단 예정 경고 1개는 유지했다.
- Node **29개 통과**. 예약을 일시정지할 때 기존 시간대·관심 종목·요일을 보존하고 장 마감 예약 본문이 서버 계약을 충족하는지도 검사했다.
- 8개 동시 워커의 예약·전송 선점에서 하나만 작업을 얻는지 확인했다. 최초 예약 트랜잭션의 잠금 경합을 발견해 슬롯 문서의 원자적 생성과 다음 시각 갱신으로 분리했다. 두 단계 사이에 중단된 상태도 복구되어 한 번만 생성·전송되는지 검사했다.
- 실제 Chrome의 새 예약 화면에서 시장 전체 예약, 장 마감/시각 지정, 종목 수정·일시정지·재개·삭제, 실제 Yahoo/CNN 미리보기, 전송 큐 등록, 응답 유실 후 동일 키 재시도, 실패 뒤 새 키 재시도, 상세 이력·새로고침 복원·계정 분리를 확인했다. 1440px·390px에서 가로 넘침과 스크립트 오류가 없었으며 `artifacts/web-briefings-desktop.png`·`web-briefings-mobile.png`를 확인했다.
- 새 브라우저 검사의 Discord 설정은 에뮬레이터 전용 가상 URL이다. 실제 Discord 네트워크 호출 없이 큐까지만 확인했다. 실패 재시도 UI는 해당 에뮬레이터 전송 이력만 명시적으로 실패 상태로 변경해 검사했으며 시장 자료·인증·API는 대체하지 않았다.
- 기존 데이터·채팅 브라우저 검사와 시장 리서치 브라우저 검사도 통과했다. 테스트 전용 모델 응답과 리서치 경계값 페이로드의 범위는 앞 절과 동일하다.

## 아직 실행하지 않은 검증

- 사용자 Firebase 프로젝트의 서비스 계정·권한·클라우드 복합 인덱스 배포 후 조회. 에뮬레이터는 복합 인덱스 존재 여부를 강제하지 않는다.
- `OPENAI_API_KEY`, `OPENAI_MODEL`을 이용한 실제 모델 응답.
- 실제 Firebase 클라우드 이메일·Google 로그인과 승인 도메인 설정. 이메일 로그인은 공식 로컬 인증 에뮬레이터에서 검증했다.
- Naver·Finnhub 실제 키 호출과 실제 OpenAI 한국어 뉴스 요약.
- 실제 Discord 웹훅으로 채널 수신 확인(키 미제공). 가격 알림·외부 MCP, Render·Vercel 배포는 이후 범위다.

실행 방법과 필요한 키는 [README](../README.md)와 [환경변수 예시](../.env.example)에 있다. 비밀 키·웹훅·서버 서비스 계정은 생성하거나 저장하지 않았다.
